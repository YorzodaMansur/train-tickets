РӮЗИ 4. МОДЕЛИ РАФТОРИ ЛОИҲА (UML)

4.1. Мафҳуми модели рафтор

Модели рафтор (Behavioral Model) қисми муҳими тарҳрезии система мебошад, ки тарзи фаъолияти система ва муносибати истифодабарандагонро бо он нишон медиҳад.

Барои сохтани диаграммаҳои UML аз барномаи Draw.io (diagrams.net) истифода мешавад. Ин барнома имконият медиҳад, ки диаграммаҳои гуногун бо истифода аз шаклҳо, хатҳо ва аломатҳои махсус сохта шаванд.

Барои веб-лоиҳаи «Фурӯши чиптаҳои қатораҳои байнишаҳрӣ» чор намуди диаграмма таҳия карда мешавад:

Use Case Diagram — диаграммаи ҳолатҳои истифода.

Activity Diagram — диаграммаи фаъолият.

Sequence Diagram — диаграммаи пайдарпайии амалҳо.

State Machine Diagram — диаграммаи ҳолатҳои объект.

Воситаи истифодашаванда: Draw.io (diagrams.net).

Сомонаи расмӣ: https://app.diagrams.net/

4.4. Диаграммаи пайдарпайии амалҳо (Sequence Diagram)

Мақсад: нишон додани тартиби мубодилаи дархост ва ҷавоб байни мусофир ва қисмҳои асосии система.

Иштирокчиёни раванд

Passenger — мусофир.

Web Interface — интерфейси веб.

PHP Server — сервери PHP.

MySQL — пойгоҳи додаҳо.

Payment System — системаи пардохт.

Тартиби иҷро

Мусофир маълумоти ҷустуҷӯи сафарро ворид мекунад.

Интерфейси веб дархостро ба сервери PHP мефиристад.

Сервер ба пойгоҳи додаҳои MySQL дархост мефиристад.

MySQL рӯйхати рейсҳои мувофиқро бармегардонад.

Сервер натиҷаи ҷустуҷӯро ба интерфейс мефиристад.

Мусофир рейс ва ҷойро интихоб мекунад.

Сервер ҳолати ҷойро дар пойгоҳи додаҳо месанҷад.

Агар ҷой холӣ бошад, сервер бронро сабт мекунад.

Мусофир пардохти онлайнӣ анҷом медиҳад.

Сервер дархости пардохтро ба системаи пардохт мефиристад.

Системаи пардохт натиҷаро ба сервер бармегардонад.

Агар пардохт муваффақ бошад, сервер фармоишро тасдиқ мекунад.

Чиптаи электронӣ сохта шуда, дар MySQL нигоҳ дошта мешавад.

Интерфейс чиптаи электрониро ба мусофир нишон медиҳад.

Тартиби сохтани диаграмма дар Draw.io

Дар Draw.io файли нав месозем.

Аз панели шаклҳо бахши UML ва Sequence Diagram-ро интихоб мекунем.

Иштирокчиёни равандро дар қисми боло ҷойгир мекунем.

Барои ҳар як иштирокчӣ хатти амудии ҳаёт (Lifeline) мегузорем.

Дар байни хатҳои амудӣ тирчаҳои паёмҳоро ҷойгир мекунем.

Самти тирчаҳо бояд тартиби фиристодан ва қабул кардани дархостҳоро нишон диҳад.

Барои шартҳои «пардохт муваффақ» ва «пардохт ноком» минтақаҳои алоҳидаи шартӣ истифода мешаванд.

Тартиби гузариш байни ҳолатҳо

Available → Reserved: брон кардани ҷой.

Reserved → Paid: пардохти муваффақ.

Reserved → Expired: гузаштани муҳлати брон.

Reserved → Available: бекор кардани брон.

Paid → Confirmed: тасдиқи фармоиш.

Confirmed → Cancelled: бекор кардани чипта.

Cancelled → Refunded: баргардонидани маблағ.

Confirmed → Used: истифодаи чипта барои сафар.

Expired → Available: озод кардани ҷой.

Натиҷа: диаграмма тағйирёбии ҳолати ҷой, брон ва чиптаро дар ҷараёни хизматрасонӣ нишон медиҳад.

Эзоҳ: Ҳолатҳои Available ва Reserved ба ҷой тааллуқ доранд, ҳолатҳои Paid, Confirmed, Cancelled, Refunded ва Used бошанд, ба фармоиш ё чипта вобастаанд. Дар системаи воқеӣ ҳолати ҷой ва ҳолати чипта бояд алоҳида идора карда шаванд.
